### 데이터 흐름

1. `readFile`: 엑셀 읽기, 번호별 묶기, 미리보기.
2. 사용자가 적용하면 `G.students`에 저장.
3. `renderScore`: 전체·교과군·교과별 평균 및 학기별 과목표.
4. `uniScore`: 대학 규칙에 맞는 과목 선택과 점수 계산.
5. `renderUni`: 대학 카드, 계산 근거, 과거 입결.
6. `renderAll` / `exportCsv`: 학생 전체 비교와 내보내기.

학생 레코드는 `{no, name, rows}`이고 과목은 `{no,name,g,t,area,subject,credit,score,avg,ach,rank,count,note}`이다. 명시적인 공통/일반/진로/융합선택 구분, 성취도 분포, 학년도, 학적·졸업 구분은 없다.

상태 `G`는 학생, 사용자 추가 대학, 선택 학생, 화면 모드, 입결 펼침 상태 등을 보관한다. `hw.students`, `hw.unis`, `hw.keep`을 localStorage에 저장하며 학생 저장은 기본적으로 켜져 있다. 저장 실패는 사용자에게 알리지 않고 무시한다. 학생 번호만으로 묶으므로 여러 반을 한 번에 합치는 용도로는 식별자가 부족하다.

## 4. 현행 계산 엔진

### 일반 성적

`wAvgRank = Σ(석차등급×학점) / Σ학점`. 등급이나 학점이 없는 과목은 제외한다. `sumCredit`은 등급 유무와 관계없이 학점을 합산한다. `avgScore`는 원점수의 단순평균이며 학점 가중평균이 아니다.

학기별 평균은 `renderScore`의 학기별 보기에서 이미 계산한다. 대학별 점수는 모든 입력 학기를 한 번에 계산하며 대학별 학기별 환산 결과표는 없다.

`to9`는 5등급 구간의 중간 누적비율 `[5,22,50,78,95]`를 9등급 구간 중간값에 선형 보간하는 추정이다. 1→약 1.55, 2→약 3.34, 3→5.00, 4→약 6.66, 5→약 8.45다. 대학의 공식 환산표나 통계적으로 검증된 예측모형이 아니다. 화면의 “0.3등급 안팎” 오차 문구를 뒷받침하는 근거도 코드/자료에서 확인하지 못했다.

### 대학 점수

| mode | 방식 | 기본 규칙 |
|---|---|---|
| matrix | 석차등급×성취도 표 → 점수/영역점수 | 동국·성신 |
| blend | 등급점수와 성취도점수 결합 | 연세·충남·강원·아주 |
| rankavg | 반영 평균 등급 → 구간 점수 | 서강 논술 |
| scale | 등급/성취도 점수표 → 평균 | 가천·서울과기·서울여·경기·삼육·가톨릭·국민 |

총 14개 규칙이다. 기본 목록은 대학·전형을 1:1로 엄격하게 구분한 목록은 아니다. 일부는 여러 전형을 한 카드로 묶는다. 사용자 추가 기능은 단순 배점, 성취도 대체, 상위 N과목 정도를 입력하며 복합 규칙 편집 기능은 없다.

`uniScore`는 교과 필터 → 공통과목 제외/필수값 검사 → 과목 점수 → 상위 N과목 선택 → 가중평균 → 총점 환산 순서다. 반영·제외 내역을 함께 반환한다. 상위 과목은 점수 내림차순, 동점이면 학점 내림차순이다. 공통과목 여부는 과목명 정규식으로 추정한다.

반환값 `avgRank`는 선택된 과목의 유효 등급 평균이다. **대학 환산점수를 역산한 공식 환산등급이 아니다.** 행렬 방식에서 같은 등급·다른 성취도는 `avgRank`가 같고 점수는 다를 수 있다. 성취도만으로 점수를 매긴 scale 과목은 점수에는 들어가도 `avgRank`에는 빠질 수 있다.

앞으로 출력 지표를 학점 가중 내신등급 / 대학 반영과목 평균등급 / 대학 환산점수 / 공식 환산등급(공식 정의가 있을 때) / 참고 추정등급으로 명확히 구분해야 한다. 점수 하나에서 등급 하나를 항상 유일하게 복원할 수 있는 것은 아니다.

|---|---|---|

| 성신여대 교과 범위 | 과학 과목 하나를 넣어도 반영됨 | 인문 기준 국영수사와 달라지고 계열 선택도 없음 |
| 가톨릭 교과 범위 | 예술 음악 성취도 A만 넣으면 100점 | 첨부 AC503의 국수영사과 범위보다 넓음 |
| 동국 빈 성적 | `score:null`, `totalPts:0` | 자료 없음이 카드 상단 0점으로 표시될 수 있음 |
| 연세 성취도 누락 | 1등급·성취도 빈칸을 70점으로 계산 | 미입력과 실제 성취도 0점을 구분하지 않음 |
| 첫 시트만 읽기 | 안내가 첫 시트, 성적이 둘째 시트이면 0행 | 시트 선택/감지 필요 |
| 학생 변경 시 학기 상태 | 새 학생 행의 학년·학기가 비면 직전 학생 값을 승계 | 실제 양식 검증과 학생별 상태 초기화 필요 |

### 엑셀·코드 대조에서 확인한 차이

- 국민대: 코드가 국수영사과·기가정보·교양까지 한 번에 평균. 엑셀의 계열별 교과와 공통·일반 85%/진로 15%를 표현하지 못한다.
- 성신여대: 코드가 사회·과학을 모두 포함하며 계열에 따른 교과 선택이 없다. 성취도 분포 감점은 주석에서 미반영을 명시한다.
- 서울과기대: `areas:[]`로 전 교과를 허용한다. 계열별 교과 및 최소 반영학점 지원 요건은 구현되어 있지 않다.
- 가천대: 제외할 과목군별 과목 수/선택 기준을 실행하지 않는다. 어떤 과목부터 제외하는지 원문 확인 후 구현해야 한다.
- 연세대: 반영과목 B의 E 또는 3단계 C 감점 미구현. 과목 유형 구분도 현재 입력 모델에 없다.
- 아주대: 사회·과학 융합선택 상위 5과목 성취도 반영 미구현.
- 충남대: 코드의 `areas:[]`는 엑셀에서 제외하는 체육·예술·교양·전문교과를 명시적으로 제한하지 않는다.
- 경기·삼육·가톨릭: 전 교과 허용 및 성취도 대체가 실제 반영교과/과목 유형 조건보다 넓게 적용될 수 있다.
- 강원대: 엑셀은 강릉·삼척·원주·춘천을 별도 대학명으로 기록하지만 코드에는 강원대 단일 규칙이다. 캠퍼스별 일치 여부는 추가 검증 대상이다.
- 서강대: 현재는 논술 교과 규칙이며, 엑셀의 지역균형 학생부교과 규칙과 다른 전형이다. 같은 대학이라는 이유로 서로 덮어쓰면 안 된다.

공통 누락은 반영 학기/졸업 구분, 과목 유형, 교과별·과목군별 가중치, 교과군별 선택/제외, 미달 과목 보정, 감점, 소수점 처리, 최소 학점 등이다. 지원자격·수능최저·출결 등은 교과 환산과 별개의 지표로 관리해야 한다.

### 파서·운영 한계

- 열 위치 고정: 번호0, 성명1, 학년2, 학기3, 교과4, 과목5, 학점6, 원점수/평균7, 성취도8, 석차등급10, 수강자수11, 비고12. 9번 열은 사용하지 않는다.
- 나이스 실제 성적 파일이 이번에 제공되지 않아 이 매핑을 실물로 검증하지 못했다.
- `parseFloat`와 반올림을 사용하며 등급 1~5, 학기 1~2, 양의 학점 등 범위 검증은 없다. 9등급제 파일을 일반 5등급 요약에 넣는 상황도 차단하지 않는다.
- 교과명을 정확한 문자열로 비교한다. 한국사 별도 표기, 교과명 띄어쓰기/별칭 차이에 대한 정규화가 필요하다.
- 학점 가중 여부가 꺼지면 계산상 학점이 1이 되어 상위 과목 동점 정렬의 학점 정보도 사라진다. 적용 대학의 실제 동점 규정 확인이 필요하다.
- CSV는 전체 학생×전체 규칙 결과이며 학기별 내보내기는 없다. 동점 학생의 전체 비교 순위는 공동 순위가 아닌 행 번호다.
- 여러 파일 병합, 반/학년도 관리, 데이터 형식 버전, 저장 실패 안내, 사용자 규칙 백업·공유 기능이 없다.

## 6. 대학어디가 입결

현행 `window.IPGYEOL`은 **13개 대학 규칙 키, 26개 연도·전형 묶음, 총 1,079개 모집단위 행**이다. 2024·2025학년도 결과이며 서강 논술 카드에는 이 데이터가 없다. 서울과기·동국은 2024만, 경기대는 한 연도에 여러 전형이 연결되어 있다.

행은 `[모집단위, 모집인원, 경쟁률, 충원순위, 환산50, 환산70, 등급50, 등급70]`이다. 코드에 직접 포함된 정적 자료이며 현재 자동 수집·갱신 기능, 원문 URL/수집일, 명시적 학교 식별자 매핑은 없다.

2026-10-20에 어디가 공개 페이지를 열어 다음을 확인했다.

- 대학별 `평가기준 및 입시결과`에 모집단위별 결과 표가 존재한다.
- `searchSyr=2026` 페이지는 “2026학년도 전형 평가기준 및 2025학년도 결과공개”를 담을 수 있다. URL 연도를 입결 연도로 그대로 저장하면 안 된다.
- 50%·70%컷은 최종등록자 중 해당 위치 성적이지 합격확률이 아니다.
- 학생부등급과 대학별 환산점수는 별도 열이며, 평가에 반영된 교과목 및 만점도 함께 확인해야 한다.
- 소수 모집단위의 미공개 등급은 0으로 처리하지 않는다.

확인 출처:

- 계명대: https://www.adiga.kr/ucp/uvt/uni/univDetailSelection.do?menuId=PCUVTINF2000&searchSyr=2026&unvCd=0000068
- 동아대: https://www.adiga.kr/ucp/uvt/uni/univDetailSelection.do?menuId=PCUVTINF2000&searchSyr=2026&unvCd=0000105

위 두 페이지 확인은 전국 대학의 최신 공개 연도, 기존 1,079행의 정확성, 수집 API·자동화 가능성을 전수 검증한 것은 아니다.

현재 화면은 `avgRank → to9` 추정값보다 70%컷이 나쁜 모집단위 수를 보여 준다. 이 수치를 합격 가능 학과 수로 해석하면 안 된다. 사용자 추가 입결 `u.past` 경로는 5등급/9등급 기준을 저장하지 않고 평균과 직접 비교하므로 특히 수정이 필요하다.

향후 입결 키는 `(대학/캠퍼스ID, 입결연도, 모집시기, 전형ID, 모집단위ID)`로 분리하고, 원문명·출처URL·확인일·등급체계·만점·지표종류·비공개상태·반영방법을 함께 저장한다. 2028 환산점수와 2024/2025 환산점수는 이름이 같아도 같은 척도로 가정하지 않는다. 정성전형의 공개 내신등급도 교과전형의 정량 환산점수와 구분한다.

## 7. 앞으로의 개발 순서

1. **결과 지표 정의와 오류 방지**: 평균등급·환산점수·추정등급을 분리하고 학기 제한, 자료 없음, 필수값 누락을 처리한다.
2. **실제 나이스 입력 검증**: 익명화된 실제 양식으로 열 탐지, 학생 경계, 병합셀, 여러 시트, 과목 유형·교과명 정규화를 검증한다.
3. **대학 규칙 데이터 분리**: 2028 엑셀에서 대학·전형 목록을 추출하되 AC열을 무검증 자동 실행식으로 바꾸지 않는다. 먼저 14개 기존 규칙의 불일치를 정리한다.
4. **규칙 엔진 확장**: 반영기간 → 교과/과목유형 → 그룹별 선발/제외 → 점수표 → 가중치 → 감점·보정 → 반올림 순서를 명시하고 적용근거를 결과와 함께 반환한다.
5. **전국 대학으로 확대**: 원문·쪽수와 엑셀 행 번호를 남기고 규칙 상태를 검증완료/일부 구현/원문 필요로 구분한다. 정성평가만 있는 전형을 정량 산출 가능으로 표시하지 않는다.
6. **어디가 입결 연결**: 대학·캠퍼스·전형 명칭을 매핑하고 연도별 데이터를 검증해 연결한다. 학과별 입결은 조회하되 성적 계산 화면은 대학·전형 중심으로 유지한다.
7. **사용 흐름 개선**: 학생·학기 성적 변화, 대학별 반영과목/점수, 입결 출처를 쉽게 확인하게 하고 내보내기·저장·백업을 보강한다.

권장 내부 구조는 입력 정규화 / 계산 엔진 / 대학 규칙 / 입결 자료 / 화면의 분리다. 프레임워크나 서버 도입은 아직 필요조건이 아니다. 브라우저 내 성적 처리 방식은 유지할 수 있다.

## 8. 이번 확인의 범위

- 추적 소스와 README, 환산 14개 규칙, 입력·저장·화면·내보내기 경로를 정적으로 확인했다.
- 제공 엑셀의 모든 자료 행을 집계하고, 전형별 반영교과 문구 차이를 조사했다.
- 기존 JavaScript 2개 블록의 문법 검사를 통과했다.
- 원본 계산 함수를 추출해 Node VM에서 가상 성적·가상 엑셀 행으로 평균, 학기 제한, 교과 범위, 빈 성적, 성취도 누락, 시트 순서, 학생 경계 동작을 확인했다. 원본 앱의 함수는 변경하지 않았다.

따라서 이 문서는 향후 개발을 시작할 수 있는 코드·데이터 구조 및 결함 목록이며, 전국 대학 산식의 정확성 인증이나 구현 완료 보고서가 아니다.
